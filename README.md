# RoadToExpert

## Cel projektu

RoadToExpert to długoterminowy projekt rozwoju kompetencji zawodowych w obszarze Quality Engineering, test automation oraz inżynierii oprogramowania.

Celem projektu jest przejście od obecnego profilu opartego głównie na automatyzacji testów w Tricentis Tosca do szerszego profilu technicznego, obejmującego:

* automatyzację frontend i backend,
* API testing,
* programowanie,
* Git i pracę z repozytoriami,
* CI/CD,
* Docker i Linux,
* cloud,
* architekturę systemów,
* praktyczne wykorzystanie AI w pracy inżynierskiej.

Projekt ma przygotować mnie zarówno do zwiększenia wartości na rynku pracy w perspektywie 6–12 miesięcy, jak i do osiągnięcia poziomu eksperckiego w perspektywie 3–5 lat.

---

## Główne cele

### Cel krótkoterminowy — 6–12 miesięcy

Zbudowanie praktycznych kompetencji wymaganych na współczesnym rynku QA Automation / Quality Engineering:

* Git
* HTTP / HTTPS
* JSON
* REST API
* Postman
* Playwright
* TypeScript
* SQL
* Azure DevOps
* podstawy CI/CD
* podstawy Docker
* praktyczne wykorzystanie AI

### Cel długoterminowy — 3–5 lat

Rozwój w kierunku szerokiego profilu Quality Engineer / Software Engineer:

* zaawansowana automatyzacja,
* CI/CD,
* Linux,
* Docker,
* Kubernetes,
* cloud,
* infrastruktura jako kod,
* architektura systemów,
* observability,
* AI-assisted engineering,
* projektowanie i utrzymywanie frameworków testowych.

## Strategia

RoadToExpert opiera się na trzech równoległych torach.

### TOR A — Market Value

Kompetencje, które mają zwiększyć moją konkurencyjność na rynku pracy w najbliższych 6–12 miesiącach.

Priorytet:

**Git → HTTP → JSON → REST API → Postman → Playwright → TypeScript → SQL → CI/CD**

### TOR B — Expert

Kompetencje budujące długoterminową wartość techniczną.

Priorytet:

**Linux → Docker → CI/CD → Cloud → Kubernetes → Terraform → Architecture → Observability → AI**

### TOR C — Career

Rozwój kariery i wykorzystanie zdobytych kompetencji:

* analiza rynku,
* CV,
* LinkedIn,
* GitHub,
* portfolio,
* projekty praktyczne,
* przygotowanie do rozmów technicznych,
* analiza ofert pracy,
* okresowa aktualizacja strategii.

## AI jako kompetencja przekrojowa

AI nie jest osobnym dodatkiem na końcu roadmapy.

Od początku projektu AI będzie wykorzystywane jako narzędzie pracy i nauki.

W szczególności:

* ChatGPT,
* GitHub Copilot,
* AI-assisted coding,
* analiza błędów,
* tworzenie testów,
* analiza API,
* generowanie danych testowych,
* refaktoryzacja,
* dokumentacja,
* analiza logów,
* nauka nowych technologii.

Każdy większy temat powinien zawierać odpowiedź na pytanie:

> Jak mogę wykorzystać AI w praktycznej pracy z tą technologią?

## Zasady nauki

1. **Praktyka ponad teorię.**
2. Każdy większy temat kończy się ćwiczeniem lub mini-projektem.
3. Wiedza ma być możliwa do zastosowania w realnej pracy.
4. Nie uczymy się technologii tylko dlatego, że jest popularna.
5. Priorytetem jest ROI nauki.
6. Roadmapa może być zmieniana wraz ze zmianą rynku.
7. Projekty mają tworzyć rzeczywiste portfolio.
8. Git jest podstawowym narzędziem pracy nad projektem.
9. AI jest wykorzystywane od pierwszego etapu.
10. Celem nie jest znajomość jak największej liczby narzędzi, lecz budowanie coraz szerszego profilu inżynierskiego.
